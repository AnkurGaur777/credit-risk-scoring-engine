| Age range (from `DAYS_BIRTH`) | 21-69 years | Days fields are negative: age = -DAYS_BIRTH / 365.25 |

## Leakage review
* Stage A uses only fields known at application time.
* Stage B aggregates only records dated **before** the application (relative days <= 0, monthly balances < 0);
  enforced by `features.before_application` and unit-tested.
* All binning, imputation grouping and encoders are fit on **train only**; the test set is touched once for final numbers.
* A single-feature AUC or IV that looks too good (IV > 0.5, model AUC near 0.9) is treated as a leakage alarm, not a success.

## Policy decisions
* `CODE_GENDER` is **never** a model input. Age-derived features are excluded by default (`CR_ALLOW_AGE=0`).
  Both are still used to **audit outcomes** by group.
* Rare categories (< 1% of train) are grouped into `__RARE__`.
